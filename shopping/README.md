# 買い物リスト（夫婦でリアルタイム共有）

ログイン不要・URL を共有するだけで、夫婦それぞれのスマホから同じ買い物リストをリアルタイムに
編集できる Web アプリです。ビルド不要の静的サイトなので、`shopping/index.html` を置くだけで動きます。

- 公開URL: `https://19tmnr89-design.github.io/heart-salon/shopping/`
- 妻: 「📋 リスト作成」モードで、食材をタップしてリストを作る
- 夫: 「🛒 買い物」モードで、店内でチェックしながらカゴに入れる

## 使い方

1. 上のURLをスマホで開く（初回に部屋が自動で作られます）
2. 右上の ⚙️ →「🔗 共有用リンクをコピー」でリンクをコピーし、LINE などで相手に送る
3. 相手がそのリンクを開けば連携完了。以降は両方の画面が数百ミリ秒で同期します

「ホーム画面に追加」するとアプリのように起動でき、一度開いた端末なら圏外でも開けます。

### リスト作成モード

- カテゴリを開いて食材をタップすると即リストに追加されます（もう一度タップで取り消し）
- 食材を追加しても、見ている場所がずれないようにスクロール位置を保ちます
- 検索ボックスはひらがなでも探せます（「とうふ」→ 豆腐、「ねぎ」→ 青ネギ・長ネギ）
- 「⭐ よく買うもの」には、買い物を完了した回数が多い品目が自動で並びます
- **数量は品目ごとに選択式**です。キャベツなら「1/4玉・半玉・1玉」、ダイコンなら
  「半分（茎側）・半分（先端側）・1本」、食パンなら「8枚切り・6枚切り・3枚・サンドイッチ用」を
  タップで選びます。複数個買うことがあるジャガイモなどは「1個・2個・3個・1袋」から選べます
- 品名・数量・💡 を1行にまとめて、一度に見える品目数を増やしています
- 選び方のコツは 💡 を押したときだけ開きます（もう一度押すと閉じます）
- 選択肢にない数量にしたいときは、品名をタップ →「その他」で数値と単位を直接入力できます
- 肉・調味料など選択肢を設けていない品目は、−／＋ で数量を増減します
- 品名をタップすると、数量・単位・カテゴリ・選び方のコツを編集できます
- マスターにない物は、一番下の「リストにない物を追加」から登録できます（単位はプルダウンで選択、
  一覧にないものは「その他（入力）」で自由に入力できます）

### 買い物モード

- 品目は**売り場を回る順**（野菜 → きのこ → 果物 → 大豆製品・加工品 → 肉 → 魚 → 調味料 → 麺類・米 → 卵・乳製品 → 飲み物 → 日用品）に並びます
- **行そのものをタップ**するとカゴ入れになります。押し間違えても下部のバーから取り消せます
- 購入済みの行をタップすると未購入に戻ります
- 選び方のコツは省略せず全文が表示されます
- 一度に見える品目数を優先して、進捗バーとチェックボタンは置いていません。
  ヘッダーも固定せずスクロールで流れます（iPhone SE で10品目が一度に見える想定）
- 「買い物を完了して履歴に保存」を押すと、リストが履歴に移って空になります
- 次回、リスト作成モードの「前回のリストを復元」で同じ品目を一括で戻せます

### 電波が弱いお店でも大丈夫

Firestore のオフライン永続化を有効にしてあるので、店内で電波が切れてもチェックは端末に保存され、
電波が戻った時点で自動的に相手の画面へ反映されます。画面上部に現在の状態（同期中／オフライン中）が出ます。

## セットアップ（Firebase 側の設定）

Firebase プロジェクトは筋トレログ（`kintore/`）と同じ `app-develop-8b413` を共用しています。
`shopping_lists` コレクションを新しく使うので、**セキュリティルールの追加が1回だけ必要**です。

### 手順

1. [Firebase コンソール](https://console.firebase.google.com/) を開き、プロジェクト `app-develop-8b413` を選ぶ
2. 左メニューの **構築 → Firestore Database** を開く
3. 上部タブの **ルール** をクリック
4. 表示されているルールに、下の `shopping_lists` のブロックを追加する
   （※ 既存の `kintore` のブロックは消さないでください。丸ごと貼り替えるなら下のコード全体でOKです）
5. **公開** ボタンを押す

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // 筋トレログ（既存）
    match /kintore/{docId} {
      allow read, write: if request.auth != null;
    }

    // 買い物リスト
    match /shopping_lists/{roomId} {
      allow read, write: if request.auth != null;
      match /{document=**} {
        allow read, write: if request.auth != null;
      }
    }
  }
}
```

6. 左メニューの **構築 → Authentication → Sign-in method** で「匿名」が**有効**になっているか確認する
   （筋トレログで既に使っているので、通常はもう有効になっています）

### このルールの意味

「Firebase に匿名ログインできた人なら、部屋IDを知っていれば読み書きできる」という設定です。
部屋IDは推測できない20文字のランダム文字列なので、リンクを知らない人がリストにたどり着くことはありません。
逆に言うと**リンクを渡した相手は誰でも編集できる**ので、共有先には気をつけてください。

### 部屋IDを控えておく

⚙️ の「部屋ID」に表示されている文字列を控えておくと、機種変更やキャッシュ削除の後でも
同じ欄に入力して「この部屋IDに切り替える」で元のリストに戻れます。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.html` | 画面のマークアップ |
| `style.css` | スタイル（ダークモード対応） |
| `app.js` | アプリ本体（Firestore との同期、描画、操作） |
| `master-data.js` | マスター食材のプリセット（139品目、11の売り場）・カテゴリ（売り場）の並び順・単位候補 |
| `firebase-config.js` | Firebase の接続設定（公開されても問題ない値） |
| `manifest.json` / `sw.js` | PWA（ホーム画面に追加・オフライン起動）用 |

## データ構造

マスター食材の本体は `master-data.js`（コード側）にあり、Firestore に保存するのは差分だけです。
そのため読み書きが非常に少なく、プリセットを増やしたいときはファイルを編集するだけで全端末に反映されます。

```
shopping_lists/{roomId}
  ├── items/{itemId}        今回買うもの
  │     name, category, quantity, unit, tip, isChecked,
  │     order, addedBy, checkedBy, checkedAt, createdAt
  ├── master_meta/{品名}     マスターの差分（編集したコツ・単位・カテゴリ）、
  │                          カスタム品目（isCustom）、使用回数（useCount）
  └── history/{historyId}   買い物完了時のスナップショット（completedAt, items[]）
```

## プリセット食材を増やす・直す

`master-data.js` の `MASTER_PRESET` に1行足すだけです。

```js
{ name: "レンコン", category: "野菜", unit: "節", yomi: "れんこん", amounts: ["1節", "2節"], tip: "ふっくら太く、穴が小さめのもの" },
```

- `category` は `CATEGORY_ORDER` にあるものを使ってください（売り場の並び順もここで決まります）
- `yomi` は検索用のひらがな読み。漢字を含む品名には付けておくと探しやすくなります
- `tip` は空文字でも構いません（空のときは画面に表示されません）
- `amounts` を書くと数量が選択式になります。省略すると −／＋ の数値入力になります
- `defaultAmount` で最初に選ばれる数量を指定できます（省略すると `amounts` の先頭）。
  たとえばキャベツは選択肢を「1/4玉・半玉・1玉」の順に並べつつ、既定を「1玉」にしています

アプリ内で「選び方のコツ」を編集した場合は Firestore 側の差分が優先されます。
