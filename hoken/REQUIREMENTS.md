# 保険整理アプリ（仮称：もしもシート）要件定義

## 0. このドキュメントについて

自分が入っている保険（民間保険・公的保険・会社の制度）を1か所に整理し、
**「自分に何かあった時に、家族のお金がどうなるのか」** を家族と共有できる状態にするための要件定義。

ヒアリング（全5ラウンド）の回答をもとに作成。実装前の合意用ドキュメントであり、
実装に着手する時点で「10. 未決事項」を潰してから着手する。

配置場所は `heart-salon/hoken/`。既存の `kintore` / `shopping` と同じく
**サーバー不要の静的Webアプリ + Firebase同期** の構成に合わせる。

---

## 1. 目的

このアプリで解決したいことは、優先度順に次の3つ。

| # | 解決したいこと | 成功の状態 |
|---|---|---|
| 1 | **もしもの時のお金の見える化** | 自分が亡くなった場合に、家族に入るお金と出ていくお金を年ごとのグラフで示し、「何年もつか」が一目で分かる |
| 2 | **保険の棚卸し・ムダ探し** | 今入っている保険を一覧化し、年間保険料の合計と、保障の重複が見える |
| 3 | **家族が困らない引き継ぎ情報** | 配偶者が閲覧モードで、契約一覧と「証券のありか」を自力で辿れる |

※「入院・手術時の請求もれ防止」は今回の目的から**外す**（対象外機能として 4.3 に記載）。

---

## 2. 利用者とモード

| モード | 利用者 | できること |
|---|---|---|
| 編集モード | 本人（自分） | 全データの閲覧・編集 |
| 閲覧モード | 配偶者 | 決められた範囲の閲覧のみ（編集UIを出さない） |

- 登録対象は **本人の契約のみ**。配偶者・子どもの契約は今回は登録しない（将来拡張の余地はデータモデルに残す）。
- 閲覧モードで見せるもの：
  - もしもの時のお金のサマリーとグラフ
  - 契約一覧（保険会社・保障内容）
- 閲覧モードで**見せないもの**：ムダ探し用の棚卸し画面、シミュレーション前提の編集UI。
- **閲覧制限は画面上の制御のみ**（誤操作防止が目的）。Firestoreのセキュリティルールでは書き込みを止めない方針。
  技術的には閲覧モードのデータも書き換え可能であることを承知のうえで採用する。

## 3. スコープ

### 3.1 MVP（今回つくる分）

1. 契約の登録・一覧・保険料集計
2. 死亡ケースの年ごとの推移グラフ
3. 上記を支える最低限の前提入力（家計・子ども・資産・公的年金の手入力）
4. 配偶者向け閲覧モード（1〜2の閲覧）
5. JSONの書き出し・読み込み
6. Firebase同期（既存 `kintore` / `shopping` と同じ合言葉方式）

### 3.2 後続リリース

- 就業不能ケースのシミュレーション
- 大病・長期入院ケースのシミュレーション
- 介護ケースのシミュレーション
- 保障の重複チェック画面（MVPでデータ構造だけ用意し、画面は後続でも可）

> 4ケースすべてを扱えるよう**データモデルは最初から4ケース分を想定して設計**し、
> 画面とロジックだけMVPでは死亡ケースに絞る。

### 3.3 やらないこと（明示的に対象外）

| 対象外 | 理由 |
|---|---|
| 入院・手術時の請求もれチェックリスト | 今回の目的から外した |
| 証券番号・口座番号・パスワード等の保存 | 漏洩リスクを負わない。「ありかメモ」だけ持つ |
| 保険証券の写真添付 | 番号が写り込むため見送り |
| 公的年金額の自動計算 | 計算ロジックのズレを避け、本人が調べた金額を手入力する |
| 更新・満了・払込完了のアラート通知 | 見直しの促しは不要との判断 |
| 払込総額と戻り（解約返戻金・満期金）の比較 | 今回は不要 |
| 配偶者・子ども・親の契約の登録 | 本人分に絞る |
| ライフイベント記録と見直し提案 | 不要 |

## 4. データモデル

保存キーは `hoken-data-v1`（localStorage）。ルートは1つのJSONオブジェクト。

```jsonc
{
  "schemaVersion": 1,
  "updatedAt": "2026-09-21T10:00:00+09:00",
  "profile":    { /* 本人 */ },
  "household":  { /* 家計の前提 */ },
  "children":   [ /* 子ども */ ],
  "policies":   [ /* 民間保険の契約 */ ],
  "companyBenefits": [ /* 会社の制度 */ ],
  "publicBenefits":  [ /* 公的給付（手入力） */ ],
  "assets":     [ /* 貯金・投資・退職金・相続見込み */ ],
  "assumptions":{ /* シミュレーション設定 */ },
  "handover":   { /* 引き継ぎ情報 */ }
}
```

### 4.1 profile（本人）

| 項目 | 型 | 必須 | 備考 |
|---|---|---|---|
| birthYear | number | ● | 生年（西暦）。年齢軸の起点 |
| pensionType | enum | ● | `kosei`（厚生年金） / `kokumin`（国民年金） |
| annualIncome | number | | 年収（万円）。表示と目安用 |
| retirementAge | number | | 定年予定年齢。団体保険の失効判定に使う |

### 4.2 household（家計の前提）

| 項目 | 型 | 必須 | 備考 |
|---|---|---|---|
| monthlyLivingCost | number | ● | 現在の月間生活費（万円、住居費・教育費を除く） |
| reduceRateWithChildren | number | ● | 本人が欠けた後の生活費削減率。既定 70%（＝現在の7割） |
| reduceRateAfterChildren | number | ● | 末子独立後の削減率。既定 50% |
| housing | object | ● | 下記 |
| funeralCost | number | | 葬儀・お墓・相続関連の一時金（万円）。初年度に計上 |
| spouse | object | ● | 下記 |

**household.housing（住居費・住宅ローン）**

| 項目 | 型 | 備考 |
|---|---|---|
| type | enum | `loan`（持ち家ローンあり） / `owned`（ローン完済） / `rent`（賃貸） |
| monthlyPayment | number | 月返済額 or 家賃（万円） |
| remainingYears | number | 残返済年数 |
| hasGroupCredit | boolean | **団信の有無**。死亡ケースでは `true` なら返済額を0にする。就業不能ケースでは原則そのまま残す |
| otherMonthlyCost | number | 管理費・修繕積立・固定資産税など、団信でも消えない費用（月額・万円） |

**household.spouse（配偶者）**

| 項目 | 型 | 備考 |
|---|---|---|
| birthYear | number | 生年 |
| currentAnnualIncome | number | 現在の年収（万円） |
| incomeAfterEvent | number | もしもの後に想定する年収（万円）。働き方を変える前提を反映 |
| workUntilAge | number | 何歳まで働く想定か |

### 4.3 children[]（子ども）

| 項目 | 型 | 備考 |
|---|---|---|
| name | string | 表示名（ニックネーム可） |
| birthYear | number | 生年 |
| coursePlan | object | 進路プラン。段階ごとに `public` / `private`、大学は `national` / `private_liberal` / `private_science` |
| independenceAge | number | 独立年齢。既定22歳。生活費の削減率切替と遺族年金の期間判定に使う |

進路から年ごとの教育費を割り当てるための**目安テーブルをアプリに内蔵**する（金額は編集可能）。

### 4.4 policies[]（民間保険の契約）

| 項目 | 型 | 必須 | 備考 |
|---|---|---|---|
| id | string | ● | 内部ID |
| category | enum | ● | `life`（生命・収入保障） / `medical`（医療・がん・就業不能・介護） / `savings`（個人年金・学資・外貨） / `nonlife`（火災・地震・自動車） |
| productType | enum | ● | プリセット（下記） |
| insurer | string | ● | 保険会社名 |
| productName | string | | 商品名 |
| status | enum | ● | `active` / `paid_up`（払込済） / `lapsed`（失効・解約） |
| startDate | date | | 契約日 |
| endDate | date | | 満了日（終身なら空） |
| isWholeLife | boolean | | 終身かどうか |
| premium | object | ● | 保険料（下記） |
| coverages | array | ● | 保障の配列（下記） |
| beneficiary | string | | 受取人（続柄で持つ。氏名は任意） |
| storageNote | string | | **証券のありかメモ**（例：自宅の金庫／会社の総務／マイページはパスワード管理アプリ） |
| contactNote | string | | 問い合わせ窓口のメモ（担当者名・部署など。電話番号は任意入力） |
| memo | string | | 自由メモ |

> **証券番号・口座番号の入力欄は設けない。** ありかメモの入力欄には「番号は書かないでください」と注意書きを添える。

**policy.premium**

| 項目 | 型 | 備考 |
|---|---|---|
| amount | number | 1回あたりの保険料（円） |
| cycle | enum | `monthly` / `semiannual` / `annual` / `lump`（一時払） |
| payUntilAge | number | 払込満了年齢（終身払なら空） |

**policy.coverages[]（保障）**— 1契約に複数（主契約＋特約）

| 項目 | 型 | 備考 |
|---|---|---|
| kind | enum | 保障種類タグ（下記）。**重複チェックの横串キー** |
| payoutType | enum | `lump`（一時金） / `monthly`（月額） / `daily`（日額） / `annual`（年額） |
| amount | number | 金額（円） |
| termYears | number | 支払期間（収入保障など）。空なら一括または終身 |
| minGuaranteeYears | number | 最低支払保証期間（収入保障保険向け） |
| note | string | 支払条件のメモ（例：がん診断一時金は1回のみ） |

**productType プリセット**
`term_life`（定期保険） / `whole_life`（終身保険） / `income_protection`（収入保障） / `medical`（医療保険） /
`cancer`（がん保険） / `disability`（就業不能保険） / `nursing`（介護保険） / `personal_pension`（個人年金） /
`education`（学資保険） / `fx_savings`（外貨建） / `fire`（火災・地震） / `auto`（自動車） / `other`

**coverage.kind プリセット（重複チェックの単位）**
`death_lump`（死亡一時金） / `death_monthly`（死亡後の月額） / `high_severity_lump`（三大疾病等の一時金） /
`cancer_lump`（がん診断一時金） / `hospital_daily`（入院日額） / `surgery`（手術給付） /
`advanced_medical`（先進医療） / `disability_monthly`（就業不能月額） / `nursing_lump`（介護一時金） /
`nursing_monthly`（介護月額） / `maturity`（満期金・年金原資） / `property`（物損） / `liability`（賠償）

### 4.5 companyBenefits[]（会社の制度）

| 項目 | 型 | 備考 |
|---|---|---|
| kind | enum | `group_life`（団体定期・群保） / `group_medical`（団体医療） / `death_retirement`（死亡退職金） / `condolence`（弔慰金） / `corporate_pension`（企業年金・DC） / `zaikei`（財形） / `stock`（持株会） |
| name | string | 制度名 |
| amount | number | 金額（円）。一時金なら総額、月額なら月額 |
| payoutType | enum | `lump` / `monthly` / `annual` |
| expiresOnRetirement | boolean | **退職で失効するか**。団体保険は `true`。棚卸し画面で「退職後に消える保障」として別表示する |
| coverageKind | enum | 4.4 の `coverage.kind` と同じタグ。民間保険との重複チェックに使う |
| storageNote | string | 手続き窓口のありかメモ（例：社内ポータルの福利厚生ページ、総務部） |

> 団体保険は民間保険と同じ保障タグを持たせることで、「医療日額が会社の団体保険と民間保険で二重」といった
> ダブりを1本の積み上げグラフで見せられるようにする。

### 4.6 publicBenefits[]（公的給付・すべて手入力）

自動計算はしない。ねんきんネット等で調べた金額をそのまま入れる。

| 項目 | 型 | 備考 |
|---|---|---|
| kind | enum | `survivor_basic`（遺族基礎年金） / `survivor_employee`（遺族厚生年金） / `widow_addition`（中高齢寡婦加算） / `disability`（障害年金） / `old_age`（老齢年金） / `sickness_allowance`（傷病手当金） / `other` |
| scenario | enum | どのケースで発生するか：`death` / `disability` / `illness` / `nursing` |
| annualAmount | number | 年額（万円） |
| startCondition | enum | 開始条件：`immediately` / `at_age`（本人/配偶者の◯歳から） / `after_months`（◯か月後から） |
| endCondition | enum | 終了条件：`youngest_child_18`（末子18歳の年度末） / `at_age`（◯歳まで） / `lifetime`（終身） / `months`（◯か月間） |
| conditionValue | number | 上記条件の数値 |
| memo | string | 調べた出典・前提のメモ（例：2026年9月にねんきんネットで確認） |

**初期表示テンプレート**：新規作成時に「遺族基礎年金」「遺族厚生年金」「中高齢寡婦加算」の3行を
**金額未入力の状態で雛形として並べ**、典型的な支給期間だけ既定値で入れておく。
金額は自分で調べて入れてもらう。入れるまではグラフに0として扱い、画面に「未入力」バッジを出す。

### 4.7 assets[]（保険以外に入ってくるお金）

| 項目 | 型 | 備考 |
|---|---|---|
| kind | enum | `savings`（預貯金） / `investment`（NISA・株・投信） / `retirement`（退職金見込み） / `inheritance`（相続見込み） |
| amount | number | 金額（万円） |
| availableAt | enum | いつ使えるか：`now`（シミュレーション開始時の初期残高） / `at_age`（◯歳時に受取） |
| ageValue | number | `at_age` の場合の年齢 |
| memo | string | メモ |

### 4.8 assumptions（シミュレーション設定）

| 項目 | 型 | 既定値 | 備考 |
|---|---|---|---|
| inflationRate | number | 1.0% | 生活費・教育費に毎年かける上昇率 |
| investmentReturn | number | 1.0% | 残高に毎年かける運用利回り |
| simulationYears | number | 自動 | 既定は「配偶者が95歳になるまで」。手動上書き可 |
| baseYear | number | 現在年 | シミュレーション起点 |

インフレ率・運用利回りは**スライダーでその場で動かせる**こと（グラフが即座に追従する）。
変更した値は保存する。

### 4.9 handover（引き継ぎ情報）

| 項目 | 型 | 備考 |
|---|---|---|
| generalNote | string | 家族へのメモ（自由記述） |

※ 契約ごとの `storageNote` / `contactNote` が主。ここは全体にかかる補足のみ。

## 5. 機能要件

### 5.1 初回セットアップウィザード（FR-01）

質問に順番に答えていくと初期データが揃う形式。

1. あなたのこと（生年・加入している年金制度・定年予定）
2. 家族のこと（配偶者の生年・収入・もしもの後の働き方／子どもの生年と進路プラン）
3. 住まいのこと（持ち家か賃貸か・ローン残年数・月返済額・**団信の有無**）
4. 暮らしのお金（月間生活費・貯金/投資の現在高）
5. 入っている保険（種類プリセットから選んで必要項目だけ入力。ここは後回しも可）
6. 会社の制度（チェックボックスで該当するものを選び、分かる金額だけ入力）
7. 公的年金（雛形3行を提示。「あとで調べる」でスキップ可）

要件：
- **どのステップからでも中断でき、途中まで保存される**。
- 未入力の項目は「未入力リスト」に残り、ダッシュボードから続きに戻れる。
- 種類プリセットを選ぶと、その保険で必要な入力項目と単位（円／日額／月額）だけが表示される。
- ウィザードは初回以降も「設定」から再実行できる。

### 5.2 契約の登録・一覧（FR-02）

- 契約の追加・編集・削除。カテゴリ（生命／医療／貯蓄／損保）でタブまたは絞り込み。
- 一覧には：保険会社・商品名・主な保障・年間保険料・状態（有効／払込済／失効）を表示。
- 1契約に複数の保障（主契約＋特約）を追加できる。
- 会社の制度は契約一覧とは別セクションで、「退職で失効」バッジ付きで表示する。

### 5.3 保険料の集計（FR-03）

- すべての保険料を**年額に換算**して合計表示する。
  - 月払 ×12 ／ 半年払 ×2 ／ 年払 ×1 ／ 一時払は年額0（別枠で「一時払の総額」として表示）
- 契約ごとの内訳を円グラフで表示。
- カテゴリ別の小計（生命／医療／貯蓄／損保）。
- 状態が `active` のものだけを合計対象とする（払込済・失効は合計から除外して別表示）。

### 5.4 保障の重複チェック（FR-04 / 後続可）

- `coverage.kind` を横串に、民間保険と会社の制度を**積み上げ横棒グラフ**で表示。
- 同じ `kind` に2件以上の給付がある場合に「重複」バッジを出す（判定はしない。並べて見せるだけ）。
- 退職で失効する分を**色分け**し、「退職後に残る保障」に切り替えるトグルを置く。

### 5.5 もしもシミュレーション（FR-05）★MVPの中核

MVPは**死亡ケースのみ**。ケース選択UIは最初から置き、就業不能・大病・介護は「準備中」と表示する。

出力：

1. **年ごとの推移グラフ**（主役）
   - 折れ線：各年末の残高
   - 積み上げ棒：その年に入ってくるお金 / 出ていくお金
   - 横軸は西暦と「配偶者の年齢」「末子の年齢」を併記
   - 残高が初めてマイナスになる年に印を付け、「◯年後（配偶者◯歳）に尽きます」と文章で出す
   - 尽きない場合は「◯年後も残高◯◯万円が残る見込みです」と出す
2. **サマリーカード**（グラフの上）
   - 一時金の合計（死亡保険金＋死亡退職金・弔慰金＋企業年金一時金）
   - 月々入ってくるお金（遺族年金＋収入保障＋配偶者の収入）
   - 何年もつか
3. **前提スライダー**：インフレ率・運用利回り・配偶者の働き方。動かすとグラフが即追従。

### 5.6 家族向け閲覧モード（FR-06）

- URLのハッシュ（例 `#view`）または同期コード入力時のモード指定で閲覧モードに入る。
- 閲覧モードでは、編集・削除・追加のUIを一切描画しない。
- 見せる画面：もしもシミュレーションのサマリーとグラフ／契約一覧（保険会社・保障内容・ありかメモ・連絡先メモ）。
- 見せない画面：棚卸しダッシュボード、前提の編集、ウィザード、設定。
- 閲覧モードであることを画面上部に常時表示する。

### 5.7 データの入出力（FR-07）

- 全データのJSON書き出し（ファイル名に日付を入れる）。
- JSONの読み込み（現在のデータを置き換え。実行前に確認ダイアログ）。
- `schemaVersion` を見て、将来のバージョン差異に備える。

### 5.8 端末間同期（FR-08）

- 既存 `kintore/sync.js` と同じ方式：合言葉のSHA-256をドキュメントIDにして、匿名認証でFirestoreを共有。
- 保存キー・コレクション名は保険アプリ用に分ける（`hoken-data-v1` / `hoken-sync-code`）。
- 競合時の扱いは既存アプリと異なり、**配列の和集合ではなく `updatedAt` が新しい方で丸ごと上書き**する
  （契約データは筋トレのログと違い、追記型ではなく編集型のため）。上書き前に確認を出す。

## 7. 計算仕様（死亡ケース）

シミュレーション年 `t = 0, 1, 2, ... N`（`t=0` が発生年）。

### 7.1 入ってくるお金 IN(t)

| 項目 | 計上ルール |
|---|---|
| 死亡保険金（一時金） | `coverage.kind = death_lump` の合計を **t=0** に計上 |
| 収入保障（月額） | `death_monthly` を `月額×12` として `termYears` の間、毎年計上。`minGuaranteeYears` を下回らない |
| 死亡退職金・弔慰金 | companyBenefits の `death_retirement` / `condolence` を **t=0** に計上 |
| 企業年金・DC・財形・持株 | `payoutType` に従い、一時金なら t=0、年金なら該当期間に計上 |
| 公的年金 | publicBenefits のうち `scenario = death` のものを、開始条件〜終了条件の範囲で年額計上 |
| 配偶者の収入 | `incomeAfterEvent` を `workUntilAge` まで毎年計上 |
| 資産の受取 | `availableAt = at_age` のものを該当年に計上 |

### 7.2 出ていくお金 OUT(t)

| 項目 | 計上ルール |
|---|---|
| 生活費 | `monthlyLivingCost × 12 × 削減率 × (1+インフレ率)^t`。削減率は末子独立前 `reduceRateWithChildren`、独立後 `reduceRateAfterChildren` |
| 住居費 | `hasGroupCredit = true` なら返済額は0にし、`otherMonthlyCost × 12` のみ計上。`false` または賃貸なら `monthlyPayment × 12` を `remainingYears` の間計上（賃貸は期間無制限、インフレ率を適用） |
| 教育費 | 各子どもの進路プランと生年から、その年に在学している段階の年額を内蔵テーブルから引き、インフレ率を適用して合計 |
| 葬儀・相続関連 | `funeralCost` を **t=0** に計上 |

### 7.3 残高

```
B(-1) = 貯金・投資の現在高の合計（assets の availableAt = now）
B(t)  = ( B(t-1) + IN(t) - OUT(t) ) × (1 + 運用利回り)
```

- 端数は万円単位に丸めて表示する（内部計算は円）。
- `B(t) < 0` となった最初の `t` を「尽きる年」とする。
- 残高がマイナスの年には運用利回りを掛けない（借金が増えるように見えるのを防ぐ）。

### 7.4 計算しないもの（割り切り）

- 死亡保険金の非課税枠・相続税・所得税は考慮しない。**税引前の金額で表示する**。
- 遺族年金の細かい支給要件（保険料納付要件、子の加算額の改定など）は判定しない。手入力値をそのまま使う。
- 画面に「税金・社会保険料は考慮していない概算です」と常時注記を出す。

## 8. 非機能要件

| 項目 | 要件 |
|---|---|
| 動作環境 | サーバー不要の静的ファイル。`hoken/index.html` を開くだけで動く。ビルド不要・外部ライブラリ不要（グラフも自前のSVG/Canvasで描く） |
| 対応端末 | PCのChrome/Edge/Safariを主対象。スマホでも閲覧・グラフ表示ができること |
| データ保存 | localStorage が唯一の出所。Firebase同期はその写し |
| セキュリティ | 証券番号・口座番号・パスワードは保存しない。保存するのは「ありかメモ」のみ。閲覧制限は画面上の制御のみで、暗号化や厳密なアクセス制御は行わない |
| バックアップ | JSONの書き出し・読み込みで復元できること |
| 公開 | GitHub Pages で `https://<ユーザー名>.github.io/heart-salon/hoken/` として使えること |
